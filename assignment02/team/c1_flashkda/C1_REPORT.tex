\begin{abstract}
FlashKDA 在 Blackwell 上仍以 SM80 世代的 \code{mma.sync} 执行矩阵计算。
本文围绕 C1 的六个问题，分析这一选择的数值和架构约束，并检验保持该指令路径时的优化空间。
对 CHUNK=16/32/64 的推导表明，直接增大分块会同时触及指数范围和有限 Neumann 求逆成本；
但 tcgen05 的 tile 限制并不意味着 CHUNK=16 的整个算法无法迁移。
我们提出状态寄存器驻留与调度联合优化，在保持原有混合精度算法和接口的条件下，
通过全部 580 项原生参考测试，其中四项覆盖最高 104 万 token。
主形状 \(T=8192,H=96,D=128\) 的 BF16-state 延迟在两张 B300 上分别降低
5.854\% 和 6.143\%；TP8 的每卡 12 头场景降低约 8\%，短序列和多序列负载则接近持平。
独立 FP32 逐 token 参考进一步区分了 kernel 的总数值误差与每 16 token 保存一次 BF16 状态的误差。
证据支持保留并优化现有 HMMA 路径，同时将 SM100 专版视为需要完整布局、同步和精度验证的研究方向。
\end{abstract}

\section{引言}
指令更新能否直接转化为端到端加速，是 FlashKDA 在 Blackwell 上的核心问题。
题面固定了 Kimi K3 的主要配置 \(H=96,D=128\)，并要求解释官方实现为何仍采用 SM80 MMA，
以及是否值得推出 SM100 专版\cite{task}。在张量并行部署中，相关并行度是每卡头数：
TP8 对应 \(H=12\)，不能用模型的总头数替代。

本文将问题分成三个层次。首先，CHUNK=16 是否由数值范围、求逆工作量和矩阵形状共同决定？
其次，新指令与更多 CTA 能否缩短有状态依赖的递推路径？
最后，在满足正确性与精度要求时，哪一种改动能相对 FlashKDA 本体产生可重复收益？
研究贡献是：给出可核算的 CHUNK 成本；建立相同形状的指令微基准与多场景端到端对照；
实现不改变数值算法的 K2 状态驻留优化；补齐百万 token 回归和独立精度诊断。
正文围绕这些问题组织，逐轮命令、失败尝试及历史探针勘误保留在实验记录中。

\section{算法与设计约束}
\subsection{KDA 的分块递推}
为便于推导，本节采用 \(S\in\mathbb{R}^{D_k\times D_v}\) 的状态方向，
kernel 实际保存其转置。设归一化后的 query、key 为 \(q_t,k_t\)，
门控的自然对数为 \(g_t\le0\)，更新系数为 \(\beta_t\in(0,1)\)。
逐 token 定义为\cite{fla}
\begin{align}
 \widetilde S_t&=\operatorname{diag}(\exp g_t)S_{t-1},\\
 S_t&=\widetilde S_t+
       \beta_t k_t(v_t-k_t^{\mathsf T}\widetilde S_t)^{\mathsf T},
 &o_t&=q_t^{\mathsf T}S_t/\sqrt{D_k}.
\end{align}
同一 head 的状态在时间方向存在依赖，不能直接把相邻 chunk 当作独立 GEMM。

对长度为 \(C\) 的 chunk，令 \(p_i=\sum_{j\le i}g_j\)，逐元素定义
\[
 K_d=K\odot e^p,\quad K_i=K\odot e^{-p},\quad
 Q_d=Q\odot e^p/\sqrt{D_k},\quad K_r=K\odot e^{p_{C-1}-p}.
\]
令 \(L=\operatorname{diag}(\beta)\operatorname{strictLower}(K_dK_i^{\mathsf T})\)，
\(M=\operatorname{lower}(Q_dK_i^{\mathsf T})\)。则
\begin{align}
 U&=(I+L)^{-1}\operatorname{diag}(\beta)(V-K_dS_{\rm in}),\\
 O&=Q_dS_{\rm in}+MU,\qquad
 S_{\rm out}=\operatorname{diag}(e^{p_{C-1}})S_{\rm in}+K_r^{\mathsf T}U.
 \label{eq:chunk}
\end{align}
FlashKDA 将归一化、门控、Gram 矩阵和 inverse 放在 token/head 并行的 K1 prepare 中，
将式 \eqref{eq:chunk} 的状态递推放在 K2 中\cite{flashkda}。
K1 是非线性操作与小矩阵计算的组合；题面提及的输入投影
\code{in_proj_qkvgfab} 是另一个 GEMM，不能用其瓶颈直接解释 K1。

\subsection{CHUNK 的数值范围、求逆与形状（问题 1）}
当前 lower bound 为 \(-5\)，门控为
\[
 g_{t,d}=-5\,\sigma\!\left(e^{A_{\log}}(g^{\rm raw}_{t,d}+b_d)\right).
\]
累计 \(\log_2\) 指数最坏幅度为 \(5C\log_2e\)。
BF16 的指数位数与 FP32 相同；当前 FP32 \code{ex2.approx.ftz}
还会冲掉 subnormal，因而需同时考察约 \(-126\) 的 FTZ 下界和 \(+128\) 的溢出边界\cite{ptx}。
不能仅将 workspace 从 BF16 改成 FP32，就认为指数范围问题已经消失。

由于 \(L\) 严格下三角，\(L^C=0\)，Neumann 级数在有限项后精确终止，
不需要额外假设 \(\lVert L\rVert<1\)。当 \(C=2^p\) 时，
\[
 (I+L)^{-1}=(I-L)(I+L^2)(I+L^4)\cdots(I+L^{C/2}).
\]
按现有 dense doubling 方式延伸，共需 \(2\log_2 C-2\) 次 \(C\times C\) GEMM。
表 \ref{tab:chunk} 给出纸面工作量；它不是 GPU 时间预测，新的三角算法也可能改变该成本。

在不改表示的最坏门控下，C=32 已先失去指数安全性，C=64 更严重。
与此同时，减少 chunk 数并不等于减少总工作：inverse 的每 token 成本反而上升。
现有 \code{SM80_16x8x16} atom 可以组成 \(16\times16\) tile，
与 C=16 的 inverse、窄投影和 shared-memory 布局一致。
这三项约束共同解释了 C=16，而不是仅凭 Tensor Core 峰值决定分块。

混合精度还必须按阶段区分：构造 \(L\) 的 BF16 GEMM 使用 FP32 accumulator，
之后转为 FP16；Neumann inverse 才使用 FP16 accumulator，最终将 inverse 写为 BF16。
上三角在使用前清零，因此该区域的溢出本身不能证明因果区域失效。
扩大 CHUNK 的精度研究应检查实际保留的下三角元素与输出。

\subsection{共同指数偏移的可行性}
正确的 per-key 缩放需跨时间共享：
\[
 c_d=(\min_i p_{i,d}+\max_i p_{i,d})/2,\qquad
 K'_d=K\odot e^{p-c},\quad K'_i=K\odot e^{-p+c},\quad
 S'=\operatorname{diag}(e^c)S.
\]
于是 \(K'_dS'=K_dS\)，Gram 矩阵的偏移逐 key 抵消；状态更新可继续用稳定的指数差
\(K_r=K\odot e^{p_{\rm last}-p}\)。这提供了扩大 CHUNK 的数学入口，
但 factor 范围、state 缩放与混合精度舍入仍需分别验证。

\section{优化方法：改变状态驻留与同步}
\subsection{从共享内存往返转向寄存器复用}
K2 每个 CTA 为一个 head/sequence 处理多个 chunk，含四个 MMA warp 和两个 load/store warp。
原路径反复通过 shared memory 取得和更新 \(128\times128\) BF16 状态。
我们的假设是：对于固定 head 的长序列，保持状态驻留并缩短输出发布等待，
比直接扩大矩阵指令更容易作用于递推临界路径。

候选保持 C=16、K1、workspace ABI 和 Python 接口，仍使用 HMMA。
每个 MMA warp 拥有 32 个 value 维度，缓存其对应的全部 128 个 key，
即每 lane 64 个 packed-BF16 32-bit 字。状态按
\(S[\mathrm{value},\mathrm{key}]\) 方向更新为
\[
 S_{v,k}^{\rm new}=
 \operatorname{BF16}\!\left(
  \operatorname{FMA}(S_{v,k}^{\rm old},e^{p_{{\rm last},k}},
                    (U^{\mathsf T}K_r)_{v,k})\right).
\]
该方向允许 cached C fragment 到下一次 B operand 的转换采用本 lane 字排列
\([0,2,1,3]\)，避免原方向的跨 lane 转置。
映射探针验证实际 CuTe copy atom，算术探针另检查转置前后 FP32 累加结果和 BF16 更新结果；
完整测试继续以原始数值语义为准。

\subsection{初始化与输出发布}
完整缓存直接加入循环会增加寄存器活跃范围和布局转换，并不自动加速。
我们把首次状态 preload 移到 chunk 循环外，使展开后的循环主体不再携带首次加载分支。
warp 私有状态使用 warp 范围同步，同时保留输入/输出 ring buffer 的 producer/consumer 协议。
输出计算结束后即可 commit，让 TMA store 与状态更新重叠；
只有最后一个 chunk 且调用方请求 final state 时，才保持原来的较晚发布顺序。

这些改动以构建开关启用，默认路径仍关闭 challenge 开关。
它们是一组联合设计，而非已证明相互独立的收益项。
后文消融只回答测过的组合，不把寄存器数量或某一条指令当作单独的因果解释。

\section{实验设计}
\subsection{环境、baseline 与计时口径}
主实验使用 B300 SXM6 AC（CC 10.3，148 SM）、driver 580.126.09、
CUDA 13.0、PyTorch 2.13.0+cu130 和 Python 3.12。
FlashKDA snapshot 为 \code{1ce47ea}，CUTLASS 为 \code{5c149f52}，
FLA 参考为 \code{a3edffc}。baseline 和候选由隔离 checkout 加载，记录实际 extension
路径与 SHA-256，避免 editable install 或运行时环境变量掩盖构建身份。
常规最终验证与补充性能实验使用不同物理 B300，所有性能比都在各自 allocation 内配对。

性能指标为 public \code{flash_kda.fwd} 的 CUDA-event 延迟，
包括 K1、K2 及其调用路径。输入与调用方 output/final-state buffer 在计时外准备，
API 自身的 workspace 分配保留。CUDA events 可能包含 CPU 发射间隙造成的 GPU 空闲，
因此它既不是 kernel-only 时间，也不是完整 CPU wall time。

每组以 A--B--B--A 顺序运行四个独立 Python 进程。
普通形状每进程 warmup=30，收集 \(100\times5=500\) 个 event 样本；
每种实现取两个 run median 的 median。
两项 \(T\ge131072\) 性能测试改用 warmup=3、\(10\times3=30\) 个样本。
定义延迟降低率 \(r=1-t_{\rm cand}/t_{\rm base}\)，速度比为 \(t_{\rm base}/t_{\rm cand}\)，二者不混用。
两次 run 不是独立设备样本；本文不据此构造过度精确的置信区间，
对小于 1\% 的差异仅描述为接近持平。

\subsection{正确性与数值精度的三层验证}
第一层是原生 \code{torch_ref} 的逐位回归，验证混合精度和边界语义是否保持。
第二层是在实际计时输入上核对 baseline/candidate 的输入、output 和 final state 的 SHA-256，
并对此前覆盖不足的 \(H=12,T=8192\) 另做原生参考对拍。
第三层是独立逐 token FP32 KDA 与 float64 数学转写，检验算法和误差来源。
FP32-state 接口内部仍转为 BF16，故比较两种接口无法代替第三层。

精度诊断固定 \(H=1,D=128\)、seed=20260911、随机 BF16 q/k/v、
标准正态 beta logits，以及幅度约 0.1 的 BF16 初始状态。
令 \(A_{\log}=0,b=0\)，扫描 raw gate 为 \(-8\)、标准正态和 \(+8\)：
分别为弱衰减、随机门控和强衰减。
同一输入前缀取 \(T=256,1024,8192\)，报告 output 与 final state 的
\(\lVert x-x_{\rm ref}\rVert_2/\lVert x_{\rm ref}\rVert_2\)，并归档 max/mean/p99 absolute error。
另只在 FP32 token 参考的每 16 token 边界把状态舍入为 BF16，
以隔离状态保存的误差；该诊断没有模拟 kernel 的其它舍入点。

\section{实验结果}
\subsection{官方复现与主性能结果}
官方 benchmark 的 B300 复现覆盖 fixed、六段不等长 varlen 和八段 \(1024\) token。

\code{HMMA.16816.F16}，主计算没有 WGMMA 或 tcgen05。

\section{架构讨论}
\subsection{tcgen05 能否局部替换（问题 2）}
所测 BF16 1-CTA tcgen05 atom 的 M 为 64 或 128\cite{ptx,cutlass}。
若保持原有 \(16\times16\) tile 的方向，padding 到 \(64\times16\) 或
\(128\times16\) 仅有 25\% 或 12.5\% 有用行工作。
但 K2 的整个 state update 是 \(128\times128\times16\)，本来就满足大 tile 条件；
窄投影 \(16\times128\times128\) 也可转置为 \(128\times16\times128\)。
因此不增大 CHUNK 并不等于数学上不能使用 tcgen05。
真实迁移成本在于线程/CTA 映射、TMEM accumulator 的生命周期、
状态方向、同步和输出布局，原有 atom 不能只改名字就替换。

\subsection{递推之外的并行度（问题 3）}
H96 的 fixed 路径只有 96 个主要递推 CTA，仍少于 B300 的 148 个 SM；
TP8 的 H12 更受并行度限制。原有 CTA 已跨多个 chunk 持续处理同一状态，
所以仅把它称为 persistent kernel 不会创造新的时间方向并行。

\begin{table}[htbp]\centering\small
\begin{tabularx}{\linewidth}{@{}p{25mm}YY@{}}\toprule
候选&潜在收益&反例或约束\\\midrule
多 head/CTA&共享固定调度开销，聚合更大矩阵&减小 CTA 数；低 H 下可能进一步降低 SM 覆盖\\
跨任务 persistent 调度&平衡多 sequence 的长度，复用部分资源&需要任务队列；固定单序列缺少额外任务，不能打破状态依赖\\
按 value 拆为 2 CTA&同一 head 的 value 方向独立，增加 CTA 数&重复 K1 workspace 读取和同步，小/大 H 的最优点不同\\
2-CTA cluster/DSM&跨 CTA 共享部分加载或使用更大 MMA&cluster barrier、分布式访问和资源要求可能抵消节省\\
时间并行扫描&将 chunk 的仿射状态变换做组合&需构造/组合更大的变换，增加计算、存储及舍入路径\\\bottomrule
\end{tabularx}
\caption{可用并行度与反例；不能从 CTA 数增加直接推出加速。}
\end{table}

同环境 value-split 对照在 H1/H4 将延迟分别从 1.2680/1.2916 ms 降到
1.1094/1.1518 ms，但 H96 从 1.7582 ms 增至 2.0066 ms。
DSM primitive 也出现比重复加载更慢的结果。
这些反例支持按每卡 head 数、序列数和长度选择路线，
不支持把“多 CTA”或某个 Blackwell 特性作为普适优化。

\subsection{是否发布 SM100 专版（问题 6）}
支持专版的论据是：D128 的状态更新可以匹配 tcgen05，
TMEM 可能减少寄存器累加压力；低 H 部署和长序列又确有临界路径空间。
若同时重做布局、稳定的较大 CHUNK 或跨任务调度，专版可能具有峰值性能价值。
反对立即替换默认路径的论据是：窄 inverse 与投影的形状仍在，
完整递推的同步、误差和 final-state 协议尚未由 GEMM 探针覆盖；
更多架构分支也增加编译、测试和维护成本。
架构专属指令应依据目标设备验证，不能将 SM100a 二进制或局部速度比外推到其它 GPU\cite{blackwell}。

我们的工程选择是保留经过验证的 HMMA 通路，并把本次联合优化作为有条件的可选实现：
长 fixed BF16-state 是已证实场景，多序列和短序列不主张明显收益。
SM100 专版值得保留研究分支；发布门槛应是相对当前最佳 HMMA 的完整 API 提升，
同时通过形状、长序列和独立数值回归。
本次结果证明现有路径仍有优化空间，也没有证明专版不可能更快。

\section{结论与可复核材料}
对 C1，CHUNK=16 的选择有数值范围、有限 inverse 成本和现有 tile 的共同依据；
tcgen05 的较大 M 约束要求重新映射，却不构成整个算法的不可行证明。
K2 的低并行度与状态依赖解释了为什么缓存和同步组织比单看峰值算力更重要。
本文的联合优化在两张 B300 上保持原生语义并取得约 6\% 主形状降延迟，
TP8 约 8\%，同时明确短序列、varlen 与 FP32 接口的有限收益。
百万 token 逐位回归和独立 FP32 精度实验分别回答了实现正确性与误差问题。
